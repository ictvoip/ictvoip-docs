Bug Reports
###########

This page explains how bug reports are submitted for the ictVoIP
platform and what happens after a report is filed.

Overview
========

Bug reports are not accepted through an open public form. Every report
is tied to a real support ticket and submitted through a one-time,
token-gated link issued by ictVoIP support. This keeps the bug queue
limited to verified, reproducible defects.

Workflow
========

1. **Email support** — Send the issue to ``support@ictvoip.ca`` with a
   clear description, expected behaviour, actual behaviour, and your
   environment details (addon version, WHMCS version, PHP version, PBX
   platform).
2. **Ticket review** — Support reviews the request and opens a WHMCS
   support ticket for tracking.
3. **Case issued** — If the issue appears to be a software defect,
   support issues a Bug Report **Case #** (for example,
   ``ICTVOIP-2026-44BB34``) and a one-time link to the bug report form at
   ``https://www.ictvoip.ca/bug-report``.
4. **Client submits** — The client completes the structured form using
   the one-time link. The report is attached to the existing support
   ticket and the client receives a confirmation email with the Case #.

After Submission
================

* The report appears in the support ticket and the ticket is flagged as
  recently updated.
* A confirmation email is sent to the client with the Case #.
* To add logs or screenshots after submitting, reply to the ticket
  email — do not open a new ticket or request a second form.

Link Rules
==========

* Bug report links are **single-use** and expire after a set period.
* A link that has been used, expired, or revoked cannot be reused —
  reply to the support ticket to request a new one.
* Only one active case exists per ticket. If a link is lost, support can
  resend it or generate a new link for the same Case #.

What is Not a Bug
=================

Configuration questions, installation help, training, and general
troubleshooting are not bug reports. Those requests are handled through
the support ticket or a paid support plan. See the
:doc:`support_policy` for details.
